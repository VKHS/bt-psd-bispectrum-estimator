# Architecture of the reference implementation

This document describes what the code in `python/btpsd/` and `rtl/` computes, how the pieces fit together, and where
the implementation deliberately differs from the architecture of the paper. All numbers quoted for the model come from
`results/*.csv` (generated by `python/scripts/run_experiments.py`) or from the unit tests; numbers from the paper are
marked *paper*.

**Status in one table**

| Layer | What exists | Evidence | Not verified |
|---|---|---|---|
| Python model (`python/btpsd`) | floating-point references and bit-accurate fixed-point models of the PSD and bispectrum paths | `python/tests/`, 119 tests in all (81 on the model, windows and tables, 7 on the transliteration, 12 on the structure of the Verilog, 9 on the simulation results, 10 on the data behind the figures); independent floating-point references, schedule properties | real EEG/EOG/EMG records (the paper's signals are not part of the repository) |
| RTL control and addressing | line-by-line Python transliteration of the Verilog (`btpsd/rtlmodel.py`) | `tests/test_rtlmodel.py` (7 tests) | typing and syntax of the Verilog text (covered by the simulation below) |
| Figures (`docs/figures/`, 22 sheets) | structure drawn from the Verilog by `btpsd/rtlparse.py` (the generator fails if a drawn state or transition is not in the source), cycle traces and state occupancy from the CI simulation (`results/rtl_*.csv`, run id and commit in `results/rtl_sim_provenance.json`), model results from `results/` | `tests/test_rtl_structure.py` (12), `tests/test_sim_results.py` (9), `tests/test_example_sheets.py` (6): the printed numbers equal the model formulas and the simulated counts | a different simulator or synthesis; see `docs/figures/README.md` |

The first simulation found two defects, both fixed: the rounded difference of the two extreme codes halves to one LSB
above the largest code, which the model carried on while the RTL wrapped it (both now clamp, see section 2), and two
testbenches read one vector past the end. The model defines the arithmetic; a testbench that passes shows that the
Verilog follows it for the vectors it is given.

## 1. Dataflow

### PSD (1024 bins from 512-sample chunks)

```
x[n] -> chunk (512) -> 512-point memory FFT (scale 1/512) -> chunk spectra A (older), B (newer)
segment s = chunks (s, s+1), hop 512

 even bins   X(2m)   = (A(m) + B(m)) / 2                                  exact
 odd bins    X(2m+1) = FD6{ D = A - B, sign-alternated }(m)               6-tap fractional-delay filter, paper Eq. 6
 window      Xw(k)   = sum_d W(d) X(k-d)                                  1, 3 or 5 taps in the frequency domain
 power       P(k)    = Re(Xw)^2 + Im(Xw)^2                                sum-of-odds squarer or multiplier
 average     acc(k) += P(k) over segments; result = acc >> avg_shift      avg_shift = ceil(log2 S)
```

`btpsd.estimator.psd_fixed` is the bit-accurate model; `rtl/bt_psd_top.v` is the hardware counterpart.

### Bispectrum (direct method)

```
x[n] -> frames (512, hop 256) -> 512-point memory FFT (1/512) -> circular 3-tap window over 512 bins
P12 = round(F(f1) F(f2) / 2^(WL-1))      T = P12 conj(F(f1 + f2))      B[f1][f2] += T,   result = B >> avg_shift
```

`btpsd.bispectrum.bispectrum_fixed` is the model; `rtl/bt_bispectrum_top.v` the hardware counterpart.
`max_bin` bins per axis are computed (128 in the model by default, `2**LOGB` in the RTL; the vectors use 32).

## 2. Arithmetic contract (shared by model and RTL)

Everything below is bit-exact between `python/btpsd` and `rtl/`; the golden vectors in `sim/vectors/` test it.

* **Format.** Two's complement, `WL` bits, `WL-1` fraction bits (code / 2^(WL-1)).
* **Rounding.** Round half up: `(x + 2^(s-1)) >> s` with an arithmetic shift; `s = 0` is the identity. `ROUND = 0` in
  the RTL selects plain truncation (floor); the model's `rounding="trunc"` is its counterpart (the vectors and
  testbenches cover `ROUND = 1` only).
* **Butterfly scaling.** Every radix-2 add or subtract is immediately followed by `>> 1` (rounded), giving 1/8 per
  radix-8 butterfly and 1/512 for the 512-point FFT, and the result is clamped to `WL` bits. The clamp matters in
  one case only: the rounded difference of the two extreme codes, `(2^(WL-1) - 1) - (-2^(WL-1))`, halves to
  `+2^(WL-1)`, one LSB above the largest code. The `(-j)` negation saturates as well; with `ROUND = 1` it cannot
  overflow (the half difference is at least `-(2^(WL-1) - 1)`), so that saturation is reachable only with `ROUND = 0`.
* **Rotation (CRU).** `y = x * exp(-j q pi/512)`, `q` in 0..1023:
  1. octant reduction: `quad = q >> 8`, `r = q & 255`; if `r > 128` then `quad += 1`, `r = 256 - r`;
  2. ROM entry `(a, b, inv)` for `r = 0..128` (129 entries, `inv` with 14 fraction bits, angle tolerance 0.01 rad);
  3. `yr = xr*a ± xi*b`, `yi = xi*a ∓ xr*b` (clockwise / counter-clockwise);
  4. one rounding: `z = round(y * inv / 2^14)`;
  5. multiply by `(-j)^quad` (swap and negate), then saturate to `WL` bits.
* **Merge.** With `D = A - B` and `idx = (m + d) mod 512`, `d = -2..3`:
  `O(m) = -j (-1)^m * sum_i h_i (-1)^idx D(idx)`, integers `h = {512, -869, 2608, 2608, -869, 512}` (12 fraction bits),
  result `saturate(round(O / 2^13))`. Even bins: `(A + B + 1) >> 1`.
* **Window.** `Xw(k) = saturate(round(sum_d W(d) X((k-d) mod 1024) / 2^10))` with integer taps (10 fraction bits):
  rect `{0: 1024}`, Hann `{-1: -256, 0: 512, 1: -256}`, Hamming `{±1: -236, 0: 553}`,
  Blackman `{±2: 41, ±1: -256, 0: 430}`. The bispectrum uses the same taps circularly over 512 bins.
* **Power and average.** `P = re^2 + im^2` is exact; accumulation is wide and the final `>> avg_shift` rounds half up.
* **Bispectrum product.** `P12 = round((F1 F2) / 2^(WL-1))` (real and imaginary part separately), then
  `P12 * conj(F3)` exactly, with `F3 = F((f1 + f2) mod 512)`.

The paper does not specify rounding modes, the constant formats of the filters, the ROM contents beyond Table 6, or
accumulator widths; the choices above are this repository's.

## 3. Memory-based radix-8 FFT (`rtl/fft512_mem.v`, `btpsd/schedule.py`, `btpsd/r8fft.py`)

In-place decimation-in-frequency FFT on eight 64-word banks, one radix-8 butterfly issued per cycle, three passes of
64 butterflies.

| Item | Rule |
|---|---|
| address | `a = 64 a2 + 8 a1 + a0` (natural order for the input) |
| bank, row | `bank = (a2 + a1 + a0) mod 8`, `row = 8 a2 + a1` |
| pass `p` combines | the eight words that differ in digit `a2` (p = 0), `a1` (p = 1), `a0` (p = 2) - always eight different banks |
| butterfly `b = 8 hi + lo`, slot `m` | bank `(m + hi + lo) mod 8`; row `{m, hi}` / `{hi, m}` / `{hi, lo}` for p = 0 / 1 / 2 |
| output twiddle exponent (units of pi/512) | pass 0: `2 b k`; pass 1: `16 lo k`; pass 2: none |
| result | the word at address `(a2, a1, a0)` is `X[a2 + 8 a1 + 64 a0]` (unload address `64 (k & 7) + 8 ((k >> 3) & 7) + (k >> 6)`) |

**Latency and the only hazard.** The pipeline has `LAT_CRU = 4` (rotator), `LAT_BFLY = 1 + 4 + 1 + 4 = 10` and
`LAT = LAT_BFLY + 2 = 12` cycles from issue to the cycle in which the written word can be read again. Pass 1 needs
the words of pass-0 butterflies 0, 8, ..., 56 first; the last of them is issued at cycle 56 of pass 0, so pass 1 can
start at cycle `56 + LAT` at the earliest instead of 64:

```
STALL = max(0, LAT - 8) = 4 idle cycles,   issue cycles = 192 + 4 = 196,   total = issue + LAT - 1 = 207 cycles
```

There is no other read-after-write hazard (`results/fft512_cycles_vs_latency.csv`). The transliteration test shows
that the stall is minimal: one stall cycle fewer corrupts the result.

`rtlmodel.write_back_slack` makes this explicit for all 64 butterflies of pass 1 and pass 2: the slack of a butterfly is
its issue slot minus the first slot in which its last input word can be read (issue slot of the producing butterfly plus
`LAT`), and a negative slack is a hazard. With the stall of 4 the smallest slack is 0 (pass 1, butterflies 0 to 7;
butterflies 8 to 15 have 8, and so on up to 56), pass 2 has between 45 and 52; with a stall of 3 the slack of pass 1
becomes -1. `fig18` draws the pipelines and this slack, `fig10` the schedule.

## 4. PSD engine (`rtl/psd_engine.v`, `rtl/bt_psd_top.v`)

Two `fft512_mem` cores form a ping-pong pair (older chunk, newer chunk). `psd_engine` reads both through their unload
ports and performs, bin by bin: merge (six taps for the odd bin, one add for the even bin) into an internal
1024-word segment RAM, the 5-tap window, the squarer and the accumulation into a 1024-word accumulator RAM
(`ACCW = 2 WL + 8` bits by default). Loading, transforming and merging are **not** overlapped. The engine is the
functional reference of the datapath of Figs. 3-5 of the paper, not a throughput-optimised design.

`mag_sq_odd.v` implements the sum-of-odds squarer (`SERIAL = 1`, `max(|re|, |im|) + 2` cycles) or a multiplier
(`SERIAL = 0`). The cycle count of the serial squarer depends on the data (see `docs/PAPER_NOTES.md`, section 4).

Simulated cost of the reference engine (`tb_psd_top`, `WL = 12`, serial squarer, 4 chunks of which the last two are
full-scale): 836 cycles for the four FFT phases (209 each) and 115 462 cycles for the three segment phases, about
38.5 k per segment, of which 21 757 cycles in total are squarer cycles of the model. The paper's overlapped design
(Table 9: 1252 cycles latency) is a different architecture; the two are not comparable.

The simulation prints the cycles of every state, so the figure is not an estimate: `results/rtl_state_occupancy.csv`
(T_INIT 1, T_CLR 1027, T_LOAD 2048, T_FFT 836, T_SEG 115 462; W_S is 30 973 of the segment cycles, which is 3 per bin
visit plus the 21 757 squarer cycles of the model, over 3 072 visits) and the residence histogram
`results/rtl_squarer_wait_hist.csv` agree with the model formulas (`tests/test_sim_results.py`; the histogram built from
the model equals the simulated one exactly). `fig19` shows the waveforms of the FFT core and the squarer, `fig20` the
cycles per state; `fig16` and `fig17` the state machines.

Accumulator width: one power value is below `2^(2 WL - 1)`, so the worst case needs `2 WL + 1 + ceil(log2 S)` bits; the
default `2 WL + 8` covers `S <= 128` segments in the worst case, real signals need far less.

## 5. Bispectrum engine (`rtl/bispectrum_engine.v`, `rtl/bt_bispectrum_top.v`)

`bt_bispectrum_top` frames the input (512 samples, hop 256: the second half of each frame is kept in a 256-word buffer
and copied to the start of the next frame), runs the FFT core, and hands the finished spectrum to
`bispectrum_engine`:

1. **Window** - five taps per bin for bins `0 .. 2*MAXB - 1` (indices modulo 512), written to two identical RAMs so that
   `Fw(f2)` and `Fw(f1 + f2)` can be read in the same cycle. Only these bins are needed because `f1 + f2 < 2*MAXB`.
2. **Triple loop** - for each `f1` one read; for each `f2` four cycles: read, rounded product `P12`, product with
   `conj(F3)`, read-modify-write of the accumulator RAM (`BACCW = 2 WL + 10` bits, real and imaginary).

By FSM inspection one frame costs roughly `32 * MAXB + 3 * MAXB + 4 * MAXB^2` cycles (about 5.2 k cycles for
`MAXB = 32`); the testbench measures 5219 cycles per frame in the engine phase (209 more for the FFT phase; B_INIT 1, B_CLR 1027,
B_COPY 1285, B_EXT 1536, B_FFT 1045, B_ENG 26 095 for the five frames of the testbench, `results/rtl_state_occupancy.csv`,
`fig20`). Worst-case
accumulator width is
`2 WL + 1 + ceil(log2 S)` bits (one product is below `2^(2 WL)` in magnitude), so the default `BACCW` covers
`S <= 512` frames. `LOGB` is limited to 8 (a 9-bit bin address).

## 6. Where this differs from the paper's architecture

| Topic | Paper | This repository |
|---|---|---|
| Scheduling | CRU shared between FFT, FD filter and window with 16 parallel branches; chunk loading, FFT, merge, window, squarer and accumulation overlap (Table 9: 205 Msps, 1252 cycles latency, 232 MHz, 0 DSP, 4834 LUT) | one butterfly per cycle in the FFT; merge, window, squarer and accumulation are sequential state machines; **no throughput, resource, power or frequency claim is made** |
| Multipliers | none (constant multiplications in the CRU as shift-add) | the merge, window and bispectrum use `*` operators, which synthesis will map to DSP slices or LUTs; resource numbers cannot be compared with Table 9 |
| FFT memory organisation | eight dual-port banks `M_1..M_8` plus `M_9` for the second chunk, two register sequences `R0..R63` and `R64..R127` (Tables 1, 2) with sixteen 8-to-1 multiplexers each, demultiplexers and a barrel shifter (15 bit in the text, 8 bit in Fig. 3, erratum 13) driven by a 15-bit main counter (7-bit pass counter, 8-bit butterfly counter) | eight 1R1W banks with an in-place conflict-free bank and row map (section 3), no register sequences, multiplexer network or barrel shifter; the schedule and the map were derived independently of Tables 1, 2, and the equivalence of the two organisations is not claimed |
| CRU ROM | Table 6 as printed (27 of 128 rows are inconsistent in the text layer, see `PAPER_NOTES.md`) | ROM generated by `python/scripts/gen_cru_rom.py` for a 0.01 rad tolerance (`data/cru_rom_generated.csv`; 129 entries, max angle error 0.0097 rad) |
| Squarer | sum of odd numbers, count assumed to be the sample code | same; cycle counts reported, see `PAPER_NOTES.md` |
| Data | EEG, EOG, EMG records from the database of the paper's Ref. [26] | synthetic signals (`btpsd/signals.py`) |

Regenerate everything generated (`rtl/cru_rom.v`, `rtl/btpsd_consts.vh`, all vectors) with `make -C sim vectors`.
`btpsd/rtlmodel.py` re-implements the address, bank, twiddle, stall, write-back, tap and sign logic of the Verilog in
Python and is tested against the model; the Verilog text itself is checked by the simulation (`make -C sim all`, run by CI
on every push). The top-level vectors end in full-scale, hard-clipped segments (`btpsd.vectors.clipped_tone`, the
bispectrum signal amplified 2.5 times and clipped), on which the model clamps 4 (PSD) and 13 (bispectrum) rounded
butterfly differences; `tests/test_vectors_stress.py` keeps that true.

Which saturating paths the vectors reach (counted in the model): the rotator output saturates 4343 times in the rotator
vectors, 72 times in the butterfly vectors and twice in the FFT vectors; the butterfly clamp fires once in the butterfly
vectors and once in the FFT vectors, in addition to the stress segments above. The saturation of the merge and the
windows (`rsat` in `psd_engine.v`, `rsat_win` in `bispectrum_engine.v`) is not reached by any vector: the Hann and
Blackman window taps sum to 1 in magnitude (Hamming sums to 1.001), and the merge would take six neighbouring differences
`D` of full-scale magnitude with matching signs, which none of the inputs approaches. The `(-j)`
negation saturation is not reached either (`ROUND = 1`, see section 2).
